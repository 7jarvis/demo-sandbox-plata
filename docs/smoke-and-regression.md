# Smoke и regression

## Принцип

- **Regression** — весь набор автотестов (API + UI). Маркер `regression`
  ставится каждому тесту автоматически (`tests/conftest.py`), отдельно его
  писать не нужно.
- **Smoke** — подмножество regression: минимальный набор, который отвечает
  на вопрос «может ли клиент пройти основной путь с деньгами и не видит ли
  чужого». Маркер `smoke` ставится явно и только по решению, описанному ниже.
- Слой (`api` / `ui`) тоже проставляется автоматически по папке теста.

## Как это работает в CI

```
push / PR ─► lint + collect ─► smoke ─► regression ─► Allure report ─► GitHub Pages
                                  │
                                  └─ красный smoke останавливает конвейер:
                                     regression на сломанной сборке не запускается
```

| Шаг | Что делает | Падает, если |
|---|---|---|
| lint + collect | ruff, mypy, сбор тестов по маркерам | ошибка стиля или типов; тест не собирается |
| smoke | `pytest -m smoke` против поднятого `docker compose` | любой smoke-тест красный |
| regression | `pytest -m regression` | любой тест красный |
| report | Allure-отчёты обоих наборов с историей трендов → Pages | — (запускается и после падений, чтобы отчёт был) |

Каждый набор публикует JUnit-проверку в PR, Allure-результаты, трейсы
Playwright упавших UI-тестов и логи приложения.

Отчёты: https://7jarvis.github.io/demo-sandbox-plata/ (regression и smoke).

## Что попадает в smoke

Тест включается в smoke, если выполнены все условия:

1. Проверяет основной успешный путь клиента или критичную защиту
   (деньги, доступ к чужому).
2. Его падение означает, что релиз выпускать нельзя.
3. Быстрый: без больших объёмов данных и без параллельных потоков.
4. Стабильный: ни одного «мигания» за последние запуски.

Граничные значения, валидация, тексты ошибок и редкие состояния —
только в regression. Для параметризованных тестов в smoke включается один
представитель (`pytest.param(..., marks=pytest.mark.smoke)`), а не все
варианты.

Ориентир по размеру: smoke — не больше 10–15 % набора и не дольше одной
минуты на тесты. Сейчас 18 из 185 (≈10 %).

## Локальный запуск

```bash
make up            # приложение на :8000
make install       # зависимости тестов и Chromium
make smoke         # только smoke
make regression    # весь набор
make ui HEADED=1   # UI-тесты в видимом браузере
make report        # Allure-отчёт последнего запуска
```

Выборочно: `pytest -m "api and not slow"`, `pytest -k payments`.
