# Тест-кейсы

Кейсы описывают поведение в бизнес-терминах: что делает клиент и что он
должен получить. Технические детали (адреса запросов, заголовки, токены)
в предусловиях и шагах не указываются — они в автотестах и в
[`openapi.yaml`](../openapi.yaml). Коды ошибок (`CARD_BLOCKED` и т. п.)
приводятся в ожидаемом результате, потому что это часть контракта, на
который опираются клиенты.

## Формат

```
### TC-<ОБЛАСТЬ>-<NN>. Название: что проверяем
Приоритет:   критичный / высокий / средний / низкий · smoke · ручной
Автотест:    путь::тест (или «нет» и почему)
Предусловия: состояние клиента и карты перед началом
Шаги:        действия в инфинитиве: открыть, ввести, нажать, оплатить
Ожидаемый результат: наблюдаемый результат и что НЕ должно измениться
```

Связь в обе стороны: у каждого автотеста в Allure есть ссылка на свой
кейс и метка `case_id`, у кейса — путь к автотесту. Ссылка из отчёта ведёт
на якорь кейса в этих файлах. Связь проверяется в CI скриптом
[`scripts/check_traceability.py`](../../scripts/check_traceability.py):
сборка падает, если тест ссылается на несуществующий кейс, кейс — на
несуществующий тест или ручной кейс не объясняет, почему он ручной.
