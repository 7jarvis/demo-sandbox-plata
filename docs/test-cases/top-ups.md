# Пополнение карты

Правила: сумма 1.00–50000.00 MXN, строго два знака после точки; баланс
не больше 500000.00. Заблокированную карту пополнить нельзя, замороженную
можно. Повтор той же операции (например, клиент нажал кнопку дважды или
приложение переотправило запрос после обрыва связи) не зачисляет деньги
второй раз: возвращается результат первой операции.

<a id="tc-top-01"></a>
### TC-TOP-01. Пополнение карты

**Приоритет:** высокий · smoke
**Автотесты:** `tests/api/test_top_ups.py::test_top_up_credits_balance`, `test_top_ups_add_up`

**Предусловия:** клиент вошёл в приложение, есть активная карта с балансом 0.00.

**Шаги:**
1. Пополнить карту на 1500.00.
2. Открыть карту.
3. Пополнить другую пустую карту четыре раза: на 1.10, 1.20, 1.01, 99.99.

**Ожидаемый результат:**
- Операция завершена, в ней указан остаток после пополнения 1500.00; баланс карты 1500.00.
- Баланс второй карты равен точной сумме пополнений (103.30) без ошибок округления.

<a id="tc-top-03"></a>
### TC-TOP-03. Недопустимая сумма пополнения

**Приоритет:** высокий
**Автотест:** `tests/api/test_top_ups.py::test_top_up_with_invalid_amount_is_rejected`

**Шаги:** пополнить карту на: `0.99`, `50000.01`, `0.00`, `-10.00`, `10`, `10.5`, `10.123`, `1e3`, пустую сумму, ` 10.00` (с пробелом), `10,00` (с запятой).

**Ожидаемый результат:** каждое пополнение отклонено с ошибкой у суммы; баланс 0.00; в истории нет операций.

<a id="tc-top-04"></a>
### TC-TOP-04. Повтор того же пополнения

**Приоритет:** критичный
**Автотест:** `tests/api/test_top_ups.py::test_repeated_top_up_with_same_key_is_credited_once`

**Шаги:**
1. Пополнить карту на 250.00.
2. Повторить ту же операцию ещё раз (как при повторной отправке после обрыва связи).
3. Открыть карту и историю.

**Ожидаемый результат:**
- Повтор возвращает ту же самую операцию с пометкой «уже выполнена».
- Баланс 250.00, в истории одна операция.

<a id="tc-top-05"></a>
### TC-TOP-05. Повтор с изменёнными данными

**Приоритет:** высокий
**Автотесты:** `tests/api/test_top_ups.py::test_same_key_with_different_amount_is_rejected`, `test_same_key_for_another_card_is_rejected`, `test_same_key_is_independent_between_customers`

**Шаги:**
1. Пополнить карту на 250.00.
2. Повторить эту операцию, изменив сумму на 300.00.
3. Повторить эту операцию для другой карты клиента.
4. Клиенту Б выполнить пополнение с тем же идентификатором операции, что и у клиента А.

**Ожидаемый результат:**
- Шаги 2 и 3 отклонены (`IDEMPOTENCY_KEY_REUSED`), балансы не изменились.
- У клиента Б пополнение выполняется как новая операция: идентификаторы операций разных клиентов не пересекаются.

<a id="tc-top-06"></a>
### TC-TOP-06. Пополнение без идентификатора операции

**Приоритет:** средний
**Автотест:** `tests/api/test_top_ups.py::test_top_up_without_idempotency_key_is_rejected`

**Шаги:** отправить пополнение без идентификатора операции.

**Ожидаемый результат:** отказ (`IDEMPOTENCY_KEY_REQUIRED`), баланс не изменился. Без идентификатора защитить клиента от двойного зачисления нельзя, поэтому такая операция не принимается.

<a id="tc-top-09"></a>
### TC-TOP-09. Максимальный баланс

**Приоритет:** средний
**Автотест:** `tests/api/test_top_ups.py::test_balance_cannot_exceed_maximum`

**Шаги:**
1. Пополнить карту 10 раз по 50000.00.
2. Пополнить ещё на 1.00.

**Ожидаемый результат:** баланс ровно 500000.00; последнее пополнение отклонено (`BALANCE_LIMIT_EXCEEDED`), баланс не изменился.

<a id="tc-top-10"></a>
### TC-TOP-10. Одновременные повторы одного пополнения

**Приоритет:** критичный
**Автотест:** `tests/api/test_concurrency.py::test_parallel_retries_with_same_key_credit_once`

**Шаги:** отправить одно и то же пополнение на 500.00 десять раз одновременно.

**Ожидаемый результат:** все десять ответов содержат одну и ту же операцию, ровно один из них — первичное выполнение; баланс 500.00, в истории одна операция.
