# Безопасность и устойчивость контракта

<a id="tc-sec-01"></a>
### TC-SEC-01. Без входа операции недоступны

**Приоритет:** критичный · smoke (профиль и список карт)
**Автотесты:** `tests/api/test_security.py::test_card_operations_require_valid_token`, `test_profile_and_list_require_valid_token`

**Предусловия:** у клиента есть карта.

**Шаги:** не входя в приложение (без сессии, с пустой и с несуществующей сессией), по очереди: открыть профиль, список карт, карту; пополнить; оплатить; заморозить; разморозить; заблокировать; открыть историю.

**Ожидаемый результат:** каждое действие отклонено как требующее входа (`UNAUTHORIZED`); карта клиента не изменилась.

<a id="tc-sec-02"></a>
### TC-SEC-02. Чужая карта выглядит как несуществующая

**Приоритет:** критичный · smoke (просмотр и оплата)
**Автотесты:** `tests/api/test_security.py::test_other_customers_card_is_not_found`, `test_unknown_card_is_not_found`

**Предусловия:** у клиента А карта с балансом 100.00; клиент Б вошёл в приложение.

**Шаги:** от имени клиента Б с картой клиента А: открыть, пополнить, оплатить, заморозить, разморозить, заблокировать, открыть историю. Открыть несуществующую карту.

**Ожидаемый результат:**
- Каждое действие отвечает «карта не найдена» — так же, как для несуществующей карты, чтобы нельзя было подобрать чужие номера.
- Карта клиента А не изменилась, в её истории только исходное пополнение.

<a id="tc-sec-03"></a>
### TC-SEC-03. Повреждённые и слишком большие данные запроса

**Приоритет:** средний
**Автотесты:** `tests/api/test_contract.py::test_malformed_body_is_rejected_and_nothing_is_credited`, `test_oversized_body_is_rejected`

**Шаги:** отправить пополнение с данными: обрезанный JSON, массив, строка, `null`, двоичные байты; затем запрос больше 16 КБ.

**Ожидаемый результат:** повреждённые данные отклонены (`MALFORMED_JSON`), слишком большие — (`PAYLOAD_TOO_LARGE`); сервер не падает, баланс не изменился.

<a id="tc-sec-04"></a>
### TC-SEC-04. Лишние поля не игнорируются

**Приоритет:** средний
**Автотест:** `tests/api/test_contract.py::test_unknown_field_is_rejected`

**Шаги:** пополнить карту на 10.00, добавив поле «валюта: USD».

**Ожидаемый результат:** отказ с ошибкой «неизвестное поле» у этого поля; деньги не зачислены. Молча игнорировать поле опасно: клиент мог думать, что пополняет в долларах.

<a id="tc-sec-05"></a>
### TC-SEC-05. Сумма числом вместо строки

**Приоритет:** средний
**Автотест:** `tests/api/test_contract.py::test_money_as_number_is_rejected`

**Шаги:** пополнить и оплатить с суммой `10`, `10.5` и `true`, переданными как числа, а не строки.

**Ожидаемый результат:** оба действия отклонены с ошибкой у суммы, в истории ничего нет. Деньги передаются только строкой с двумя знаками, чтобы избежать ошибок плавающей точки.

<a id="tc-sec-06"></a>
### TC-SEC-06. Единый формат ошибок и идентификатор запроса

**Приоритет:** средний
**Автотесты:** `tests/api/test_contract.py::test_error_shape_and_request_id`, `test_unknown_path_uses_error_contract`

**Шаги:**
1. Открыть несуществующую карту.
2. Обратиться к несуществующему адресу API.

**Ожидаемый результат:** обе ошибки в одном формате (код, сообщение, детали); в ответе тот же идентификатор запроса, что отправил клиент, — по нему поддержка находит запрос в логах.
