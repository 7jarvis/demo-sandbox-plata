# Веб-интерфейс

Бизнес-правила подробно проверяются на уровне API (остальные файлы этого
раздела). Здесь — то, что видит клиент: сценарии проходят через интерфейс,
результат отображается верно, ошибки понятны и показаны у нужного поля.

<a id="tc-ui-01"></a>
### TC-UI-01. Регистрация и вход через интерфейс

**Приоритет:** высокий · smoke
**Автотест:** `tests/ui/test_ui_auth.py::test_register_and_sign_in`

**Предусловия:** телефон и email не зарегистрированы.

**Шаги:**
1. Открыть страницу «Create an account».
2. Заполнить имя, телефон и email, нажать «Create account».
3. На странице входа нажать «Get code».
4. Ввести код и нажать «Sign in».

**Ожидаемый результат:**
- После регистрации открыта страница входа с сообщением «Registration complete…», телефон уже подставлен.
- На странице кода показан телефон, на который отправлен код.
- После входа открыта страница «My cards», в шапке имя клиента, показано пустое состояние «You have no cards yet».

### TC-UI-02. Ошибки в форме регистрации

**Приоритет:** средний
**Автотесты:** `tests/ui/test_ui_auth.py::test_registration_form_shows_field_errors`, `test_registration_with_taken_phone`

**Шаги:**
1. Открыть регистрацию и нажать «Create account», ничего не заполняя.
2. Заполнить форму телефоном уже зарегистрированного клиента и отправить.

**Ожидаемый результат:**
- Шаг 1: под каждым полем своя ошибка, поля отмечены как неверные (в том числе для экранного диктора).
- Шаг 2: ошибка «This phone number is already registered.» у поля телефона; введённые имя и email сохранились в форме.

### TC-UI-03. Ошибки при входе

**Приоритет:** средний
**Автотесты:** `tests/ui/test_ui_auth.py::test_wrong_code_shows_attempts_left`, `test_sign_in_with_malformed_phone`

<a id="tc-ui-05"></a>
### TC-UI-05. Выпуск карты

**Приоритет:** высокий · smoke
**Автотест:** `tests/ui/test_ui_cards.py::test_issue_card`

**Предусловия:** клиент вошёл, карт нет.

**Шаги:**
1. На «My cards» нажать «Issue a card».
2. Ввести название «Subscriptions» и лимит `1500`, нажать «Issue card».
3. Вернуться на «My cards».

**Ожидаемый результат:**
- Открыта страница карты: сообщение «Card issued.», название, статус Active, баланс 0.00 MXN, лимит 1500.00 (сумма без копеек дополнена), «No transactions yet.».
- На «My cards» плитка карты со статусом, балансом и номером в виде маски.

<a id="tc-ui-14"></a>
### TC-UI-14. Блокировка через диалог

**Приоритет:** критичный · smoke (блокировка)
**Автотесты:** `tests/ui/test_ui_card_operations.py::test_block_card`, `test_cancel_block`, `test_block_requires_reason`

**Предусловия:** активная карта с балансом 250.00.

**Шаги:**
1. Нажать «Block card», в диалоге нажать «Cancel».
2. Нажать «Block card», не выбирая причину нажать «Block permanently».
3. Выбрать причину «Stolen» и нажать «Block permanently».

**Ожидаемый результат:**
- Шаг 1: диалог закрыт, карта активна.
- Шаг 2: диалог не закрывается, карта активна.
- Шаг 3: сообщение «Card blocked permanently.»; статус Blocked; пояснение с причиной stolen; блоков пополнения и оплаты нет; баланс 250.00 MXN сохранён.
